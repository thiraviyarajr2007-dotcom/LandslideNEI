## 8. Rollback Strategy

If any file move or deletion causes an unexpected issue, the following rollback mechanisms are in place:

1. **Staged External Moves:** Files selected for `MOVE_OUTSIDE_PROJECT` are **never deleted**. They are transferred with folder hierarchy intact (e.g. into an external archive directory `C:\SIH_Landslide_Archive\` or external drive). Restoring them is a simple fast file copy/move back into `C:\SIH Landslide\data\raw\...`.
2. **Git Versioning:** All source code (`src/`, `api/`, `dashboard/`, `scripts/`, `tests/`), models (`model/`), specifications (`LANDSLIDENEI.spec`), and configuration files are tracked in Git. Any accidental modification can be instantly inspected via `git status`.
3. **Post-Cleanup Automated Verification Script:** Immediately after any future cleanup execution, the following verification suite must be executed:
   - `.\dist\LANDSLIDENEI\LANDSLIDENEI.exe --check-health`
   - `.\dist\LANDSLIDENEI\LANDSLIDENEI.exe --test-operational-workflow`
   - `python -m pytest tests/` (if `venv` is present)
   If any check fails, rollback is initiated immediately before committing any changes.
